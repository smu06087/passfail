# Logic Maze (로직 메이즈) 모드 기획 및 요구사항 정의서

## 1. 개요 (Concept)
- **컨셉**: 사용자가 작성한 코드로 가상의 로봇을 조종하여 미로를 탈출하는 **자동화 알고리즘 대결 모드**.
- **핵심 목표**: 단순히 길을 찾는 것이 아니라, 주어진 API를 활용해 **최소한의 자원(에너지 코스트)으로 가장 효율적인 로직**을 설계하는 능력을 겨룸.

## 2. 핵심 게임 메커니즘

### 2.1 에너지 코스트 시스템 (Energy Cost)
하드코딩을 방지하고 코드 최적화를 유도하기 위해 두 종류의 비용을 합산하여 순위를 결정함.
- **정적 비용 (Static Cost)**: 코드 작성 시 특정 API를 사용한 횟수에 비례.
    - 이동/액션 함수 사용 시: 각 2코스트
    - 센서/상태체크 함수 사용 시: 각 1코스트
- **동적 비용 (Runtime Cost)**: 프로그램 실행 중 실제로 동작이 일어날 때마다 누적.
    - `moveForward`, `turnLeft/Right`, `useSwitch`, `pickUp`: 각 5코스트
    - `isWallAhead`, `readValue`, `getCurrentTileType`: 각 1코스트
    - `say`: 0코스트 (디버그용)

### 2.2 실시간 스트리밍 실행 (Interactive Execution)
- **방식**: 서버에서 Java 프로세스를 실행하고, `STDOUT`을 실시간으로 캡처하여 WebSocket으로 전송.
- **특징**: 
    - 무한 루프 코드도 중단 없이 실시간 애니메이션 재생 가능.
    - 사용자가 언제든 '중단(STOP)' 가능.
    - 로봇의 말풍선(`say`)과 디버그 콘솔 로그를 실시간으로 확인.

### 2.3 스마트 절차적 맵 생성 (Procedural Generation)
- **경로 보장**: 맵 생성 후 BFS 탐색을 통해 입구에서 출구까지의 경로가 반드시 존재함을 검증.
- **논리적 선후관계**: 문(Door)은 항상 주요 길목에 배치하며, 해당 문을 여는 스위치(Switch)는 문에 막히기 전 구역에 반드시 배치.

## 3. 난이도별 상세 설계

| 난이도 | 맵 크기 | 주요 기믹 및 요구 역량 |
| :--- | :--- | :--- |
| **EASY** | 7x7 | 기초 제어문 (`if`, `for`) 활용. 장애물 최소화. |
| **MEDIUM** | 7x7 | 스위치와 문 상호작용. 조건부 탐색 로직 필요. |
| **HARD** | 10x10 | 복잡한 미로 구조. 본격적인 탐색 알고리즘(BFS, DFS) 요구. |
| **VERY_HARD** | 10x10 | **순차 수집 미션**: 에너지 볼을 오름차순으로 수집해야 출구 개방. 정렬 및 복합 자료구조 활용 필수. |

## 4. 로봇 제어 API (Robot API)

- **액션**: `moveForward()`, `turnLeft()`, `turnRight()`, `useSwitch()`, `pickUp()`
- **센서**: 
    - `isWallAhead()`: 전방 장애물 유무 확인.
    - `getCurrentTileType()`: 현재 타일 종류 반환 (START, EXIT, SWITCH, DOOR, ITEM, EMPTY).
    - `readValue()`: 현재 타일에 적힌 숫자 읽기 (ITEM 전용).
- **디버그**: `say(String msg)`: 로봇 머리 위 말풍선 및 콘솔 로그 출력.

## 5. UI/UX 구성
- **사이드바**: 사용할 수 있는 API 리스트와 맵의 심볼 범례(Legend) 표시.
- **메인 뷰**: 캔버스 기반의 미로 시뮬레이션 및 타 참여자 로봇 실시간 동기화.
- **디버그 콘솔**: 서버에서 스트리밍되는 로봇의 상태 로그를 누적 표시.
- **실시간 HUD**: 참여자별 실시간 누적 코스트 표시를 통한 경쟁 심리 자극.

## 6. 기술 스택 및 아키텍처
- **언어**: Java (서버 사이드 실행), JavaScript (프론트엔드 렌더링).
- **통신**: Spring WebSocket (STOMP) 기반 양방향 스트리밍.
- **보안**: 서버 사이드 실행 시 샌드박싱 및 실행 단계 제한(MAX_STEPS) 적용 준비.

## 7. 고도화된 기술 기능 (Update)

### 7.1 배치 스트리밍 및 프리페칭 (Batch Prefetching)
- **최적화**: 명령어(CMD)를 행동 하나당 보내지 않고 50개 단위 청크로 묶어 전송하여 네트워크 부하를 98% 감소시킴.
- **프리페칭**: 클라이언트 큐의 명령어가 20개 미만일 때 서버에 `MORE` 신호를 보내 다음 배치를 미리 가져옴으로써 애니메이션 끊김 방지.
- **백프레셔(Backpressure)**: 서버 버퍼가 가득 차면 Java 프로세스를 일시 정지시켜 무한 루프로 인한 서버 자원 고갈 방지.

### 7.2 완벽한 논리-물리 동기화 (Strict SYNC)
- **Wait-Ack 루프**: Java 로봇이 행동 출력 후 서버의 `OK` 신호를 대기하게 하여, 프론트엔드 애니메이션과 Java 로직 실행 속도를 1:1로 일치시킴.
- **내부 시뮬레이션**: Java `Robot` 클래스가 내부적으로 벽 충돌을 계산하여 서버 측 좌표와 클라이언트 측 좌표의 오차를 0으로 유지.

### 7.3 정산 및 순위 결정 로직 (Settlement)
- **승리 판정**: 1순위 - 최저 에너지 코스트(Score), 2순위 - 빠른 제출 시간(FinishedAt).
- **자동 정산**: 모든 참여자가 `FINISHED` 혹은 `EXITED` 상태가 되면 서버가 즉시 최종 순위를 계산하고 방을 종료.
- **연결 유예 정책**: 연결 끊김 시 3분(일반) 또는 30초(전원 종료 대기)의 유예 시간을 부여 후 자동 기권 처리.

### 7.4 프론트엔드 모듈화
- **관심사 분리**: 
    - `logicMazeEngine.js`: 캔버스 렌더링 및 물리 엔진.
    - `logicMaze.js`: 웹소켓 통신 및 에디터 이벤트 제어.
    - `logicMaze.css`: 전용 스타일 시트.
    - `fragments/battleLibs.html`: 계층적 라이브러리 의존성 관리.
